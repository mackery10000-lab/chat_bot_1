# 인물 상호작용 수정 및 실제 API 검증

## 수정 범위

- 탐험가는 처음 만난 승객에게 재회 인사를 하지 않는다. 정차 질문에는
  정차 방법을 아는지 답하고, 제동 장치를 탐사 도구로 오인하지 않는다.
- 개인적인 탑승 동기·직업 소개는 관찰과 기록에 대한 호기심으로 답한다.
  실종 사건을 소개하는 진행 대화는 신문 지급과 같은 서버 사건으로 처리한다.
  사건 소개 전에는 자유 생성 문맥과 최종 대사에서 실종 정보를 공개하지 않는다.
- 노인은 정차 방법을 모른다고 답하며, 표를 가져가는 사람을 목격했는지와
  청소하는 사람이 지나간 기억을 구분한다. 도난이나 범인을 확정하지 않는다.
- 승무원은 “열차가 안 멈춰요” 같은 관찰을 이상 현상 질문의 답으로 인정한다.
  무관한 잡담과 단순 수긍을 이전 의뢰의 수락으로 사용하지 않는다.
- 기관사는 다음 역인 아지산역으로 가지 못해 반복 중이며, 분기기가 잠겨 있고
  비밀번호 입력이 실패한다는 관계를 설명한다. 화면 선택지와 안전 대체 응답도
  같은 내용을 유지한다. 연도 증거와 최종 조작의 기존 조건은 유지한다.
- 청소원은 주인에게 들은 실제 외형 설명을 간접화법으로 전달해도 이해한다.
  “구멍이 있는지는 모르겠어요” 같은 미확인 특징은 정답 근거로 사용하지 않는다.
  노인의 증언과 같은 물건의 두 특징을 한 답변에서 확인해야 한다는 규칙을 유지한다.
- 명확한 거절·가정·임의의 상태 변경 선언에는 인물이 짧게 답한다.
  아이템 지급·문 개방·연도 인정·엔딩을 실제로 처리하지 않는다.
- 승인된 말머리와 본문이 같은 감탄사로 시작하면 말머리를 생략한다.

## 검증 방법

`tools/live_dialogue_stress_cases.py`는 다섯 인물과 여러 진행 단계에 대해
서로 다른 한국어 발화 200개를 네 배치로 검사한다. 배치당 50개이며,
발화 수·실제 모델 호출 수·검사 수를 구분해 저장한다.

각 사례는 실제 Flask 요청으로 얻은 검수용 체크포인트에서 시작한다.
`LiveScenarioRunner`는 프로세스 안에서만 서비스 인스턴스를 바꾸고 임시 SQLite를
사용한다. 사용자 저장 데이터와 `.env`는 변경하지 않는다. API 키·헤더·프롬프트와
SDK 오류 본문은 검수 파일에 저장하지 않는다.

검사는 질문의 핵심에 답했는지, 아이템을 받을 조건이 맞는지, 장소·남은 기회·
확인 화면·엔딩·공개 정보가 허용 범위 안에 있는지 확인한다. 실제 대사도 별도로
검토해 무관한 반복, 성격 이탈, 빈 응답, 과한 대체 문구를 확인했다.

안부 질문이 현재 화면 선택지와 의미가 같아 대화 단계만 진행되는 경우와,
비밀번호 질문으로 기관사의 설명을 듣는 경우는 정상이다. 증거 없이 연도를
인정하거나 실제 조작 없이 분기기를 여는 행위와 구분해서 검사한다.

자동 검사와 대사 검토는 이 코퍼스의 결과이며, 모든 가능한 문장의 자연스러움을
증명하는 것은 아니다. 진행 결과는 계속 서버가 결정한다.

## 재실행

아래 명령은 실제 API를 호출한다. 오프라인 테스트에는 API 비용이 발생하지 않는다.

```powershell
.\runtime\python.exe -X utf8 -m unittest discover tests

.\runtime\python.exe -X utf8 tools/check_live_scenario.py --suite tools.live_dialogue_stress_cases:run_prepare --max-calls 5 --run-id dialogue-fixtures --export-checkpoints
$env:TRAIN_DIALOGUE_STRESS_SOURCE = "$PWD\.local\live-scenario-qa\dialogue-fixtures\report.json"

foreach ($batch in @('explorer', 'elder_cleaner', 'attendant', 'driver')) {
    .\runtime\python.exe -X utf8 tools/check_live_scenario.py --suite "tools.live_dialogue_stress_cases:run_$batch" --max-calls 110
}

.\runtime\python.exe -X utf8 tools/check_live_scenario.py --suite tools.live_dialogue_parity_cases:run_suite --max-calls 100 --export-checkpoints
```

최초 검사에서 실패한 기록은 삭제하지 않는다. 수정 후 검증과 구분해 같은 오류를
추적할 수 있도록 남긴다. `dialogue-summary.json`과 `transcript.md`에서 실제 질문,
응답, 검사 결과를 확인할 수 있다.
