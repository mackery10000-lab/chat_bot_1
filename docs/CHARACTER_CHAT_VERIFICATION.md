# 인물 자유 대화 검수 — 2026-11-08

검수 대상은 [인물 대화 규칙](CHARACTER_CHAT.md)이다. 실제 설정의 모델 `gpt-6-luna`와 기존 API 키를 사용했으며, 환경 파일과 플레이어의 기존 저장 기록은 변경하지 않았다. 호출 없는 회귀 검사와 실제 API 대화를 구분해 기록한다.

이후 피드백 커밋 복원과 새 배경 병합을 마친 작업본에서도 다섯 인물과 추가로 60회 대화했다. API 90회 호출·753개 검사에서 실패가 없었고, 응답 문맥과 말투도 검토했다. 아래 최초 검수 집계와 별도인 [병합 후 기록](../.local/live-scenario-qa/feedback-merged-dialogue/transcript.md), [복원 검증](FEEDBACK_RESTORATION.md)을 참고한다. 현재 전체 Python 회귀 검사는 176개를 통과했다.

## 검수 방법

실제 Flask 요청으로 시나리오를 진행하고, 그 과정에서 얻은 인물별 체크포인트를 임시 SQLite 저장소에 복사해 질문한다. 최종 응답뿐 아니라 대화 전후의 아이템·열람·공개 조건·현재 장소·출입·입력 기회·엔딩 상태를 비교한다. 자유 대화에서 허용되는 이력·리비전·일반 대화 횟수 변화는 진행 변화와 구분한다.

인물 질문, 인사·날씨·식사, 무관한 요리·정치 정보, 설정 변경·관리자 사칭·내부 지시 공개 요구를 다섯 인물에게 보낸다. 이어지는 개인 대화, 청소원에게 설명 도중 잡담한 뒤 표 찾기, 승무원의 부탁 앞에서 잡담에만 "네"라고 답하기, 기관사의 증거 확인 전후도 별도로 확인한다. 수치 판정과 함께 실제 질문·응답을 직접 읽어 맥락과 말투를 검토한다.

## 발견한 문제와 수정

- 탐험가에게 자기 상황을 말하는 "열차에 탔는데 내리지를 못했어요"가 과거 행동 보고로 해석되어 진행되지 않았다. 현재 가능한 작성 대사와 같은 입력은 해당 대화 선택으로 정규화하고, 자기 상황 설명과 타인의 과거 행동 인용을 구분하도록 수정했다.
- 승무원과 잡담한 뒤 "네"라고 답하자 이전에 제안된 의뢰를 수락한 것으로 처리될 수 있었다. 직전 응답의 대화 종류를 저장하고, 자유 대화 뒤의 짧은 수긍은 잡담으로 처리한다. 의뢰를 받으려면 대상이 드러나는 명시적 수락이 필요하다.
- 새 인사에 직전 개인 질문의 답을 반복하는 응답이 있었다. 현재 입력을 모델 자료의 마지막에 놓고, 새 발언에 직접 응답하도록 생성 지침을 수정했다.
- 보호 검증이 자연스러운 레시피 거절과 허용된 인물 사실까지 막는 경우가 있었다. 전문가 지식 제공과 모른다는 응답을 구분하고, 진행과 무관한 확정 인물 사실의 허용 범위를 조정했다.
- 청소원이 자기 설명 끝에 상대의 말을 받아주는 "그러시구먼요"를 불필요하게 붙이는 응답을 발견했다. 수긍 표현은 상대 발언에 실제로 수긍할 때만 쓰도록 조정했다. 실제 직업 대화 3회에서 불필요한 수긍 표현 없이 질문에 답하는 것을 확인했다.
- 승무원의 직업 동기·보람 질문에 자연스럽게 답했어도, 일반 명사인 "목적지"가 들어 있다는 이유로 전체 응답이 모름 대사로 대체되는 문제가 있었다. 일반적인 직업 감상에 쓰인 단어와 실제 역명·미공개 증언을 구분하도록 검증 범위를 조정했다. 생성기에 전달하는 지식의 비공개 단서 제거는 유지했다. 수정 후 직업 질문 2회에서 실제 모델의 자연스러운 답변이 모름 대사로 대체되지 않고 전달되는 것을 확인했다.

이전 검수의 정치 정보 회피 답변에 "최신 지지율은 잘 모른다"는 표현이 들어가 실패한 항목은 검사 문구의 오탐이었다. 최신 정치 사실을 제공한 코드 오류와 구분했으며, 수정한 검사로 재실행했다. 중간 실행의 실패 수치를 최종 통과 수치에 합산하지 않았다.
