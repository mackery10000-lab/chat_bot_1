# 탐색 화면 인물 배치 보정

다섯 인물의 대화용 초상화를 탐색 화면에 그대로 축소하면서 생긴 자세·크기·가림·접촉 문제를 보정했다. 대화 중의 기존 초상화와 성격·시나리오·소지품 규칙은 유지한다. 승무원실 안에서는 중복되는 뒤쪽 기록철 상호작용을 제거하고 펼쳐진 운행 서류만 남겼다.

| --- | --- | --- | --- |
| 탐험가 | `public/assets/images/characters/explorer-seated.png` | `[160,485,420,630]` | 왼쪽 좌석 쿠션에 앉은 자세. 다친 발을 아래로 내리고, 가까운 좌석 테두리가 다리 일부를 가림 |
| 노인 | `public/assets/images/characters/elder-seated.png` | `[760,485,420,630]` | 오른쪽 쿠션에 앉아 지팡이를 잡음. 보이는 신발을 통로 위로 맞추고 앞좌석 테두리 가림 적용 |
| 청소원 | `public/assets/images/characters/cleaner-working.png` | `[480,425,330,495]` | 통로 왼쪽에서 몸을 숙여 걸레질. 다리·신발·걸레가 이어지며 바닥에 접촉 |
| 승무원 | `public/assets/images/characters/attendant-standing.png` | `[110,170,484,726]` | 출입문 왼쪽에 서며 발은 문턱의 바닥 높이, 키는 문 높이에 맞춤. 문·손잡이·점검 덮개를 가리지 않음 |

다섯 이미지 모두 기존 얼굴·머리·옷을 참조한 내장 `image_gen` 결과다. 투명 PNG 원본과 [사용한 프롬프트](../public/assets/images/characters/README.md)를 저장했다. 실제 실행은 각 배경과 같은 캔버스에 합성한 `scenes/car2-explorer.png`, `car3-elder.png`, `car3-cleaner.png`, `crew-door-attendant.png`, `engine-driver.png`를 사용한다.

## 합성과 상호작용

- 기존 배경은 원본 그대로 사용한다. 인물별 톤은 객차의 따뜻하고 어두운 조명에 맞추고, 좌석·발·걸레 아래에 낮은 알파의 접촉 그림자를 합성한다.
- 가장 가까운 좌석의 나무 테두리와 기관실 운전 의자의 등받이는 인물보다 앞에 놓인다. 인물 자체를 잘라 새 PNG를 수정하지 않고 정의 파일의 가림 윤곽으로 합성한다.
- 가림 후의 인물 알파가 220 이상인 구간을 2px 높이로 나누어 추적한다. SVG `clipPath`의 정규화 좌표를 사용하므로 작은 화면에서도 같은 윤곽을 유지한다. 다리 사이, 지팡이 옆, 걸레 주변의 빈 공간과 접촉 그림자는 대화를 시작하지 않는다.
- 포인터와 키보드 포커스는 같은 대상을 강조한다. 호버로 위치나 크기를 움직이지 않고 밝기·윤곽만 약하게 강조한다.
- 탐색용 그림을 누르면 같은 NPC의 기존 대화 화면을 연다. 대화 종료 후 같은 위치로 돌아온다. 정전 중에는 숨기며, 손전등 마스크는 인물과 배경을 함께 어둡게 한다. 통로 앞문도 기존 진행 조건에 따라 이동할 수 있다.
- 이번 승무원·기관사 보정에서는 네 원본 배경과 앞서 보정한 세 인물·보관함 자산 50개의 해시가 유지된다.
- 승무원실의 뒤쪽 닫힌 기록철은 배경의 일부로 남고 클릭 등록·강조 레이어·보고서 지급 연결은 제거한다. 이전 `inspect desk` 요청은 보고서를 발견하거나 열지 않으며 실제 운행 서류를 살펴보도록 안내한다. 펼쳐진 서류의 발견·열람·승무원에게 제시하는 진행 조건은 유지한다.

정의는 `config/scene_layout.json`, 생성은 `tools/build_scene_assets.ps1`, 등록은 `public/assets/images/scenes/registration.json`, 화면 연결은 `registeredHotspot()`이다. 최종 13개 레이어의 871,284개 유효 픽셀을 확인했고, 배경 추출물의 원본 RGB도 일치한다.

## 검증

`node tools/check_gameplay_ui.mjs --scenes-only --screenshots`는 1440·390·320px에서 인물의 불투명한 픽셀을 실제 클릭해 같은 NPC가 열리는지, 투명·가림 영역이 클릭을 가로채지 않는지, 키보드 Enter·대화 종료·문 이동·손전등이 이어지는지 확인한다. 각 인물의 샘플 수와 누락·잘못된 클릭 진단은 `actor-hit-metrics.json`에 남긴다. 실행할 때 지도 접기 애니메이션이 끝난 다음 대화 종료 버튼을 검사한다.

최종 [브라우저 검사](../.local/gameplay-ui-qa/1794133744230/result.json) 227개가 통과했다. [인물 윤곽 진단](../.local/gameplay-ui-qa/1794133744230/actor-hit-metrics.json)은 세 화면 크기에서 불투명 인물 6,806개·투명/가림 6,708개 표본의 누락과 오작동이 모두 0이었다. 뒤쪽 닫힌 기록철을 실제로 눌러도 문서가 열리지 않고 운행 서류만 조사되는지 확인했다. JavaScript 예외와 자산 요청 실패도 없다. 최종 모바일 화면과 대화 전후 화면은 같은 검사 폴더에 있다.

Python 회귀 검사 186개, JavaScript 구문, 실행기 준비 검사를 통과했다. 비교용 작업 전 자산과 배치·해시 기록은 `.local/character-placement/`, 승무원·기관사 추가 보정 기록은 `.local/staff-placement/`에 있다.
