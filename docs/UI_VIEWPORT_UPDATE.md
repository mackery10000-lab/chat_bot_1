# 화면 크기·가독성·이동 연출 수정

## 화면 크기 대응

게임 화면은 현재 창의 높이와 너비를 모두 사용한다. CSS grid가 안내도와
대화 입력 영역에 필요한 공간을 먼저 확보하고, 남은 공간에는 장면을 원본
비율 그대로 담을 수 있는 최대 크기로 배치한다. 배경·인물·문·클릭 영역은
하나의 좌표계를 사용하므로 창 크기가 달라져도 위치가 어긋나지 않는다.
페이지 전체를 확대하거나 가로·세로를 따로 늘리지 않는다.

- 넓은 가로 창: 장면 옆에 안내도와 대화 입력 영역을 배치한다.
- 세로 창: 안내도, 장면, 입력 영역을 위에서 아래로 배치한다.
- 안내도를 펼치면 실제 공간을 확보해 메뉴나 인물을 덮지 않는다.
- 창 크기 변경, 대화 시작·종료, 안내도 접힘 상태에 맞춰 장면 크기를 다시 계산한다.
- 대화 글자는 화면 전체를 transform으로 축소하지 않고 14~20px로 다시 배치한다.
- 화면 전체를 보기 위한 페이지 스크롤은 없다. 긴 기록이나 대화는 해당 영역 안에서 읽는다.

Unity의 [Canvas Scaler와 앵커](https://learn.unity.com/tutorial/working-with-ui-in-unity),
Godot의 [다중 해상도와 비율 유지](https://docs.godotengine.org/en/4.5/tutorials/rendering/multiple_resolutions.html)를
참고했다. 이 프로젝트의 배경은 손으로 배치한 클릭 좌표를 포함하므로,
카메라 영역을 임의로 자르거나 늘리는 대신 원본 장면을 온전히 보존하고 UI를 재배치한다.

구현: `public/assets/css/viewport.css`, `public/assets/js/chatbot.js`, `templates/chat.html`.

## 글자와 보관함

일반 게임·퍼즐·시작 화면 본문은 로컬 나눔고딕의 실제 Regular/Bold를 사용한다.
대사와 시작 화면 이야기에는 로컬 나눔명조 ExtraBold를 적용한다. 게임 대사는
외부 폰트 CDN을 기다리지 않는다. 장식용 제목과 간판은 기존 표현을 유지한다.

보관함 기록은 `tools/print_inventory_records.ps1`로 생성한다. ‘노인의 증언’의
전용 고딕 본문을 다른 기록과 같은 나눔명조 ExtraBold로 바꾸고, 14종 기록의
글자 픽셀에 적용하던 무작위 투명도 마모를 제거했다. 종이·책의 질감과
‘바랜 종이’, ‘구멍’의 단서 강조는 유지한다.

## 게임 규칙과 이동

- 손전등 사용 버튼은 3호차가 어두울 때만 표시한다. 서버도 다른 장소나
  이미 밝아진 3호차에서의 사용을 거절한다.
- 최종 목적지는 ‘아지산’과 ‘아지산역’을 모두 정답으로 인정한다.
  연도 증명, 비밀번호, 마지막 기회 등 기존의 다른 조건은 유지한다.
- 실제 장소가 바뀌면 전용 ‘이동 중…’ 장면을 최소 1,000ms 표시한다.
  이미지가 느리면 준비될 때까지 유지하고, 캐시된 이미지에도 최소 시간을 지킨다.
- 지도, 문, 자유 입력 등은 동일한 장면 준비 경로를 사용한다.
  같은 칸 선택, 실패한 이동, 일반 대화에는 이동 연출을 띄우지 않는다.
- 이동 중에는 게임 영역을 inert 처리하고 종료·오류 시 이전 조작 상태를 복구한다.
  시작할 때의 로딩 문구는 별도로 유지한다.

## 검증 명령

```powershell
.\runtime\python.exe -m unittest discover tests
node tools/check_movement_transition.mjs
node tools/check_viewport_ui.mjs --software-renderer --no-sandbox
node tools/check_gameplay_ui.mjs --inventory-only --software-renderer --no-sandbox
```

검증 도구는 격리한 저장 데이터와 로컬 모델 응답을 사용한다.
사용자의 저장 기록과 실제 AI API는 사용하지 않는다.

2026-11-11 검증: Python 회귀 테스트 205개, 이동 수명주기 6개,
보관함 브라우저 검사 578개, 10가지 해상도·40개 화면 조합의 브라우저 검사
426개가 통과했다. 실제 이동 화면은 캐시 방문을 포함해 1,002~1,007ms
표시되었다. 안내도를 다시 펼칠 때 그림이 사라지던 합성 레이어 문제를
수정하고, 화면 픽셀 검사로 펼친 지도 그림의 표시도 확인했다.
