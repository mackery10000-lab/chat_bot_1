# 실제 모델 연결

원본 .env를 그대로 사용한다. 포함 변수는 OPENAI_API_KEY와 OPENAI_MODEL이며 파일 생성·복사·수정 단계가 없다. 모델은 기존 OPENAI_MODEL 설정을 그대로 따르며, 설정이 없을 때만 코드 기본값 gpt-4o-mini를 사용한다. 비어 있지 않은 프로세스 환경 변수가 있으면 원본 베이스와 같이 우선한다.

services/generator.py의 기존 DemoGenerator 클래스는 실제 OpenAI Responses API를 호출한다. 이름의 Demo는 원본 클래스명 보존을 위한 것으로, 데모 대화 모드가 아니다.

interpret는 입력의 의도·대상·수신자·부정·가정·외형 특징과 대화 종류를 JSON Schema로 받는다. 진행 대화는 실제 모델이 승인된 말머리를 선택하고 서버 확정 대사와 결합한다. 인물·세계관 질문과 가벼운 잡담, 무관한 요청의 회피 응답은 현재 인물의 제한된 프로필·시간 인식·최근 대화로 실제 모델이 그때그때 구성한다. 설정을 바꾸려는 요청은 인물별 혼란 응대로 처리한다. 기존 문자열 반환 계약은 유지한다.

비진행 대화의 기본 자료는 data/knowledge/character_profiles.json이다. 소소한 취향·직업 경험은 구성할 수 있지만 새 단서·정답·정확한 나이·입사 날짜를 만들지 않는다. 진행 대사의 승인 검증과 비진행 대사의 경계 검증을 구분한다. 인물에게 허용하지 않은 지식을 전체 시나리오에서 가져와 답하지 않는다. 분류와 검증의 목적은 [자유 대화 규칙](CHARACTER_CHAT.md)을 참고한다.

reasoning 또는 reasoning_effort 옵션을 보내지 않는다. store=False를 사용하고, 빈 응답·미완료·구조 오류·원문과 맞지 않는 해석을 검사한다. 외부 오류 원문·자격 증명은 사용자 응답과 로그로 전달하지 않는다.

의미 해석은 진행 권한이 아니다. 증거 지급·입장·퍼즐·마지막 시도와 엔딩은 GameEngine이 판단한다. API 장애가 난 자연어 턴은 상태를 확정하지 않는다. 실제 대화 품질은 모의 모델을 쓰는 단위 검사와 구분해 검수한다.
