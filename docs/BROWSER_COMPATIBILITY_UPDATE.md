# 엔딩·두루마리·시작 문구 호환성 보완 · 2026-11-12

## 수정 범위

이번 작업은 화면 표시와 브라우저 기능 대체에 한정한다. `services/`의 게임 판정, 대화 정책, 인물 설정, 시나리오 JSON, API와 저장 형식은 수정하지 않았다. 기존 미커밋 변경도 유지했다.

### 성공·실패 결과창

- `Array.at()` 호출을 기존 배열 인덱스 조회로 바꿨다.
- `ui-runtime.js`에 앱의 대화상자만 다루는 어댑터를 추가했다. 기본 `showModal()`을 우선 사용하고, 기능 부재나 호출 예외가 있을 때 별도 배경·초점 제한·닫기/취소 이벤트로 대체한다. 브라우저의 전역 프로토타입은 수정하지 않는다.
- 대체 대화상자의 Escape도 기존 취소 핸들러를 거친다. 최종 결과창은 Escape로 닫히지 않는다. 퍼즐의 Shadow DOM 입력도 키보드 초점 순환에 포함한다.
- 완료된 게임은 배경·인물 이미지 로딩을 기다리지 않는다. 장면 렌더링에서 예외가 나도 서버가 확정한 `good`/`bad` 결과만 사용해 결과창을 표시한다. 진행 중인 게임의 오류를 성공·실패로 바꾸지 않는다.
- 기존 영상 오류·정지 타임아웃과 함께 실제 미디어 상태를 주기적으로 확인한다. `ended`/`timeupdate` 이벤트가 누락되어도 마지막 프레임과 재생 상태를 확인해 결과창으로 넘어간다. 종료 시 모든 감시 타이머를 정리한다.
- 결과 이미지가 실패하면 깨진 이미지를 숨기고 배경색과 실제 결과 문구·다시 시작 버튼을 표시한다.
- `aspect-ratio`, `dvh`, `cqw`가 없는 경우 결과창 비율·높이·글자 크기를 대체한다. 장면과 안내도도 비율을 직접 계산한다.
- 기존 최종 확인과 실패 직후 기관사 대사 순서는 유지한다.

### 두루마리

- 브라우저별 Web Animations API와 완료 Promise 분기를 하나의 프레임 기반 종이 이동으로 통합했다.
- 매 프레임 현재 종이 높이를 참조하므로 주소창, 키보드, 화면 회전·확대에 따른 크기 변화가 진행 중인 움직임을 취소하지 않는다.
- 빠르게 반대 방향으로 누르면 현재 보이는 길이에서 이어진다. 프레임이 멈추는 WebView에서도 안전 타이머가 최종 상태와 입력 잠금을 정리한다.
- 기본 `inert`가 없는 경우에도 접힌 지도는 Tab 이동에서 제외하고 이동 중 클릭을 차단한다.
- OS/게임의 ‘움직임 줄이기’ 설정에서는 기존처럼 움직임을 생략하되, 펼침·접힘 상태와 입력 가능 여부는 정상 완료한다.

### 시작 문구

- 페이지 숨김/복귀와 뒤로가기 캐시 복원 때 남은 글자와 지연 시간을 유지한다. 복귀 즉시 전체 문장을 표시하던 처리를 제거했다.
- 숨겨진 동안 타이핑을 멈추고 다시 보이면 이어 쓴다. 글자 속도 설정이 없거나 예외를 내도 기본 속도로 완료한다.
- OS의 ‘움직임 줄이기’ 설정에서도 글자 순차 표시는 유지한다.
- 시작 화면 장식의 `ResizeObserver`와 미디어 쿼리 변경 이벤트도 기능 부재 시 기존 창 크기 이벤트/구형 리스너로 대체한다.

## 검증 결과

- 기존 화면 검사: **519개 통과**, 10개 크기·40개 배치. 실제 장면 비율, 버튼 접근, 대화 기록, 안내도, 시작 문구, 엔딩 오류 처리 포함.
- 기존 게임 회귀 테스트 `test_smoke.py`: **122개 통과**.
- 대화 보존·안내서·청소원 힌트 회귀 테스트: **3개 통과**.
- 신규 호환성 검사: 전체 실행 **68개 통과**. 구형 기능 부재와 CSS 기능 부재를 모의하고, 영상 재생 거부·응답 정지·종료 이벤트 누락·장면 렌더링 예외·이미지 실패를 주입했다. 화면 처리 전후 저장된 게임 상태가 같은지도 확인했다.
- 후속 빠른 검사 **68개 통과**: 실제 잘못된 증거 제출, 마지막 기관사 대사, 올바른 목적지·연도 최종 확인, 다시 시작 흐름을 포함한다.
- 최종 확인·퍼즐 키보드 집중 검사 **7개 통과**. 기본 대화상자와 최신 배열 API가 없는 상태에서도 실제 API 판정을 거쳐 성공/실패 결과창에 도달했다.
- JavaScript 문법 검사와 `git diff --check` 통과.

검사 도구는 `tools/check_browser_compat_ui.mjs`이며 기본 실행은 정상 영상의 실제 재생도 포함한다. `--quick`은 정상 영상 재생 반복을 생략하고 실패/대체 경로를 검사한다. `--quick --flow-only`는 최종 확인 흐름과 퍼즐 키보드를 집중 확인한다. 모두 별도 임시 저장소와 오프라인 모델을 사용한다.

기존 `check_gameplay_ui.mjs`의 영상 완료 검사도 단일 `ended` 이벤트 대신 실제 다음 화면을 확인하도록 맞췄다. 이 도구의 전체 과거 UI 검사를 모두 재실행했다는 의미는 아니다.

## 검증 한계와 실제 기기 확인

자동 검증은 Windows의 Chromium 153에서 수행했다. Edge는 이 호스트에서 디버깅 응답이 없거나 실행 직후 종료되어 완료하지 못했다. Safari/WebKit 및 iOS 실기기를 직접 실행한 결과는 아니다. 기능을 제거한 Chromium 검사는 특정 기능 부재에 대한 증거이며 다른 엔진 전체의 호환성을 보장하지 않는다.

실제 Safari/iOS 배포 확인에서는 정상 종료와 영상 실패 각각의 성공·실패 결과, 결과창 다시 시작, 주소창 변화 중 안내도 펼침/접힘, 시작 문구의 앱 전환·뒤로가기 복원을 확인한다. ‘움직임 줄이기’를 켰을 때 안내도 움직임이 생략되는 것은 의도된 접근성 동작이다.

플랫폼 동작 참고: 기본 모달은 배경 입력을 제한하며, 대체 구현도 해당 경계를 유지한다. [MDN showModal](https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/showModal). 시각적 뷰포트 크기 변화는 별도의 resize 이벤트를 발생시킬 수 있으므로, 그 이벤트만으로 종이 움직임을 취소하지 않는다. [MDN VisualViewport resize](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport/resize_event).
