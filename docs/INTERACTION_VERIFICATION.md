# 배경 강조와 청소원 대화 검증

검증일: 2026-11-01, 로컬 Windows 환경.

## 청소원 대화 오류

재현 입력: `누렇게 바랜 종이에 구멍이 뚫려있는 승차권 보신적 있으신가요?`

기존에는 질문형 문장이 외형 설명 보정에서 제외되었다. 모델이 이 입력을 `분실물의 모양을 직접 설명한다` 선택지로 연결하면, 입력창을 여는 시나리오 응답이 실제 특징 판정을 대신했다.

이번 수정은 이미 알고 있는 외형을 전달하며 물건을 찾는 질문과, 외형 자체를 묻는 추측을 구분한다. 현재 입력에서 근거를 확인한 설명은 선택지 분기보다 먼저 판정한다. 다른 물건의 특징, 명시적인 부정과 가정, 독립적인 부분 설명을 합산하는 경우에는 승차권을 지급하지 않는다.

노인의 증언 획득·열람 후 작성하는 경로를 회귀 검사했다. 모델이 입력창 선택지나 이전 단계 선택지를 잘못 반환하는 경우도 포함했다. 실제 연결된 모델로 재현 입력을 실행해 다음 응답과 아이템 저장을 확인했다.

> 누렇게 바랜 종이에 구멍이 뚫린 표 말씀이시군요. 여기 있습니다. 어르신의 승차권을 찾아드릴 수 있어 다행입니다.

동일 요청 ID 재전송은 저장된 결과를 반환하며 승차권을 중복 지급하지 않았다. 실제 모델 검증과 자동 테스트는 별도 임시 저장소를 사용했다.

## 강조 레이어

- 첨부 배경 5개는 SHA-256 비교로 원본 바이트와 일치함을 확인했다.
- 투명 레이어 12개의 불투명 픽셀 1,202,100개를 검사해 원본 좌표와 RGB 값이 모두 같음을 확인했다.
- 6개 장소 × 5개 화면 너비(320, 390, 768, 1024, 1440px)에서 중립 레이어와 배경을 스크린샷으로 비교했다. 390px에서는 배율 2도 적용했다. 좌표·크기 차이는 없었으며, 경계의 알파 합성 반올림 오차는 8비트 색 채널 기준 최대 1단계였다.
- 마우스와 키보드 강조, 각 대상의 클릭 영역, 데스크톱·모바일 인물 대화, 서류 열람, 출입문과 제어 장치 열기, 덮개 열기 → 레버 내리기 → 승무원실 입실을 확인했다.
- 탐색 중에는 배경에 그려진 인물을 강조한다. 대화 중에는 기존 표정별 초상화를 표시한다. 강조 효과는 크기·위치·비율을 변경하지 않는다.

## 기관사 대화 UI 수정 — 2026-11-02

PNG 헤더의 실제 크기를 비교했다. 기관실과 승무원실은 모두 **1739×1392px**다. 다른 객차는 1호차 1402×1122, 2호차 1235×853, 3호차 1196×798, 승무원실 출입문 1754×1169px로, 프로젝트 전체가 단일 이미지 규격을 쓰지는 않는다. 기관실의 배경과 두 강조 마스크는 같은 캔버스와 좌표를 사용한다. 기관실 배경은 재생성하거나 늘리지 않았다.

이전 배포 ZIP의 JavaScript와 CSS를 별도 로컬 서버에서 제공해 재현했다. 1440×900 화면에서 선택지의 위쪽은 y=1281px, 입력창은 y=1304px로 화면 밖이었다. 1052px 너비로 표시한 안내도 약 350px와 기관실 약 840px가 화면 높이를 초과한 것이 원인이다. 기존 기관사 진입 시 자동 스크롤은 화면을 453px 내려 배경 위쪽을 잘랐고, 크기 변경이나 다른 복귀 경로를 해결하지 못했다. 새로고침 시에는 별도로 `updateDialogue()`가 입력 동작이 없다는 이유로 저장된 대사를 숨겼다.

대화 중에는 안내도를 비례 축소하고, 헤더·안내도·선택지·입력창의 실제 높이를 제외한 영역에 원본 비율의 장면을 맞춘다. 장면의 너비와 높이가 함께 바뀌므로 배경이나 강조 좌표가 왜곡되지 않는다. 화면·선택지·힌트 영역 크기가 바뀌면 다시 계산하고, 좁은 장면에서는 도구 버튼도 작아진다. 저장된 현재 인물의 마지막 발언은 새로고침 시 복원한다.

재검증 명령은 `node tools/check_dialogue_ui.mjs`다. 별도 임시 저장과 오프라인 응답을 사용하며 기존 게임 저장이나 실제 AI 호출에 영향을 주지 않는다. 설치된 Chromium, Node 22 이상 또는 기존 `ws` 패키지, `runtime/python.exe`를 사용한다. 자동 스크롤 없이 대사창·선택지·입력창·대화 종료 버튼의 화면 내 위치와 클릭 가능 여부, 원본 이미지 비율, 선택지 진행, 직접 입력, 새로고침, 보관함 복귀와 창 크기 변경을 검사한다. 결과와 화면은 실행별 `.local/dialogue-ui-qa/` 폴더에 저장한다. 비교용 이전 ZIP은 `DIALOGUE_UI_BASELINE_ZIP` 환경 변수로 지정할 수 있다.

최종 브라우저 검사 **83개 통과**, 실패와 JavaScript 예외 **0개**다. 1440×900, 1366×768, 1024×768, 768×1024, 390×844, 320×568에서 실제 기관사 클릭·선택지·직접 입력·대화 복원을 검사했다. 대화 도중 1440×600, 1440×480, 844×390으로 바꾸는 경우와 다른 인물 4명도 통과했다. 결과는 `.local/dialogue-ui-qa/1793582943190/checks.json`, 수정 전 증거는 `.local/dialogue-ui-qa/1793582800485/checks.json`에 있다.

기존 Python 테스트 117개, JavaScript 구문 검사와 Windows 실행기 서버 검사가 통과했다. 키보드가 열려 화면이 극도로 낮아진 경우에는 최소 장면 높이를 유지하며 일반 스크롤을 허용한다.
